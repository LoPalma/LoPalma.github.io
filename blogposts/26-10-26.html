Bad Apple!! on the C preprocessor

There's a rule, or saying, I don't quite know: "if it can display two colors, it can run bad apple". Turns out CPP can do that. First, I created a python script to turn the original video in a specially devised format consisting of about 300000 lines of #ifdef directives. Then I creates a much smaller header file to decode said format, essentially creating a super tiny VM whose "ISA" consists of "W(n)" and "B(n)" directives, where W and B are for white and black respectively, and n is the number of pixels to draw. This was fun but the pure, CPP decoded video runs at like 2-3fps. To make it actually run at 30fps I created an "impure" version which is implemented as an actual C program instead of leveraging the poor C preprocessor, and this version runs beautifully at 30fps. You can try both out by cloning the source, which is on my github. No preprocessor was harmed in the making of this project.
